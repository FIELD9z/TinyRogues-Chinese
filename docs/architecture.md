# 架构与验证边界

## 运行流程

```text
完整对话／原始说明模板／完整界面文本
                    ↓
      按上下文查询独立 JSON 译文目录
                    ↓
       中文完整句／保留变量的中文模板
                    ↓
   游戏原有逐字显示、数值填入、格式与图标处理
```

`src/Core/` 负责 JSON 结构、校验、层级和匹配，不引用游戏或 BepInEx。插件项目将这份源码编译进单个插件 DLL；核心测试可独立运行。

`src/Plugin/Adapters.cs` 是游戏适配层。对话的三个入口先翻译整句，并保护当前对话正文不被普通 TMP 文本入口反复处理。选项翻译保留原来的回调、提示和取消选项标记。属性描述在通用数值填入前处理；技能和特质说明只在原有渲染调用期间临时换用中文描述，调用完成后恢复字段。

界面通过 TMP 文本赋值、格式化完成后的文本及预制界面启用事件处理。中文字体加入原字体的后备字体列表，保留游戏字体和图标。没有按固定频率扫描并替换所有屏幕文本。

职业背景和精通说明在完整原文进入 TextMeshProxy 样式处理前翻译。不要给仅返回字段的简单原生 getter 安装 Harmony 补丁：IL2CPP 会把不同类乃至不同返回类型的方法合并到同一段机器码，托管参数类型或前缀中的类型检查不能保证 ABI 安全。本项目曾在 MetaPerk.Description 上确认这个问题，已移除该类补丁。精通标题的专用格式化入口按 canonical 名称翻译；其他完整样式标签仅在整段标签内容有精确词条时处理，不拆词翻译。

## 匹配规则

匹配以完整源文本和上下文为依据；`id` 是维护标识，不是游戏查询键。空格、换行、大小写均有意义，不自动裁剪。普通条目不会用字符串前缀猜测完整句，也不会把任意英文单词逐个替换。

查找层级：先个人覆盖包，再内置包；同一层按 `priority` 从高到低，再按文件路径排序。每个文件中先查当前上下文，再查 `*` 通用上下文；精确条目先于模板条目。个人通用覆盖也可能覆盖内置的具体上下文，因此歧义用词应写具体上下文。

`kind: template` 支持受限变量：`{number:amount}`、`{key:binding}`、`{text:item}`，以及必须有精确名称译文的 `{term:food}`。数值、按键和文本捕获值原样回填；term 名称可翻译并保留已确认的样式标签，未知名称不匹配。整句匹配有长度和超时限制。译者无需编写正则。不要为一个漏翻问题添加可以吞掉任意句子的宽泛模板。

## 武器与装备说明

武器和装备的触发器、周期效果及嵌套说明，在完整描述调用期间临时换用中文模板；原生方法完成或抛出异常后恢复字段。动作名称使用独立上下文，不修改攻击定义和计算参数。

组合说明在游戏完成语义着色后处理。`WeaponCards` 只识别有明确属性行的武器卡和稀有度、类别、装备负重等结构明确的装备卡。卡片正文使用完整行模板；`DisplayValues` 处理已知枚举名称、数值范围和状态列表。跨颜色标签的动作名称先按完整值匹配，保留原有标签及数值。普通对话不使用这些卡片规则。

## 热重载与失败处理

文件检查只关注自身译文目录和覆盖目录。读取全部文件、校验并构造新目录成功后，才交换当前目录引用。失败会在日志输出 `Pack reload rejected`，保留旧目录。热重载影响之后进入翻译入口的文本；已显示的界面不保证立即重绘，可重新打开对应界面验证。

如果游戏方法签名改变，插件拒绝安装不完整的适配并移除自身补丁。加载时发现已加载的其他翻译栈也会禁用自己。安装流程仍要求只保留一套汉化，不能仅依赖加载时检测来处理所有顺序和第三方冲突。

## 哪些测试不能证明

核心测试证明匹配、覆盖和格式保护等行为，不能证明游戏所有场景都已覆盖。原生自测需要实际游戏运行环境，用于验证适配入口、逐字显示、字体和数值行为，也不能代替完整游玩回归。

发布前应分别记录：数据校验结果、核心测试结果、原生自测结果、手动检查的游戏场景及剩余问题。译文条目数量和抽取候选数量都不能换算成可靠的全游戏完成百分比。
